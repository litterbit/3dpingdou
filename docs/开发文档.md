# 开发文档

拼豆图纸转透明像素图工具。纯前端、无后端，所有处理在浏览器本地完成。技术栈：Vite + React + TypeScript，Vitest 测试。

详细算法原理见 [算法说明.md](./算法说明.md)，本文只讲工程结构与日常开发。

## 常用命令

```bash
npm install        # 安装依赖
npm run dev        # 本地开发
npm test           # Vitest，含真实图纸回归测试
npm run build      # tsc --noEmit 类型检查 + vite 构建
```

推送 `main`/`master` 后 `.github/workflows/pages.yml` 自动发布 GitHub Pages。

## 目录结构

```
src/
├── main.tsx               # 入口，挂载 App
├── domain/                # 纯算法层，不依赖 React / DOM（ImageData 有降级实现，可在 Node 下跑测试）
│   ├── pixel.ts           # 汇总导出（export *），对外唯一入口，勿在这里写实现
│   ├── types.ts           # Raster / Roi / GridGeometry / PixelMatrix 等全部接口
│   ├── helpers.ts         # clamp / median / rgbAt / distance / colorKey 等底层工具
│   ├── roi.ts             # ROI 归一化
│   ├── grid.ts            # 图纸网格检测：梯度投影 → 谐波拟合周期 → comb 相位 → 格内一致性仲裁（detectGrid）
│   ├── occupancy.ts       # 图纸占位分析：逐格墨迹 inkRatio、贯穿线剔除、三级 Otsu 阈值
│   ├── matrix.ts          # 环形区域取色、recognizeMatrix 生成像素矩阵
│   ├── repair.ts          # 角接悬空块检测（floatingBlockOffsets）与渲染（renderMatrix）
│   ├── quantize.ts        # Lab 凝聚式颜色量化（quantizeColors、rgbToLab）
│   ├── classify.ts        # 图片类型判断：格线支持率区分 图纸 / 像素图（classifyImage）
│   ├── fft.ts             # radix-2 + Bluestein 任意长度 FFT（像素图网格数估计用）
│   └── pixelart.ts        # 像素图管线：FFT/梯度估计格子数 → comb 细化周期 → 网格线吸附 → 采样置空量化
└── ui/                    # 界面层，全部状态集中在 App
    ├── App.tsx            # 状态 + 业务流程（四步状态机），不含具体界面细节
    ├── types.ts           # Step / Tool / GridState、步骤常量
    ├── helpers.ts         # imageToRaster / hex / canvasPoint 等 UI 工具
    ├── styles.css         # 全部样式（CSS 变量 + 类名）
    ├── Field.tsx          # 数字输入框
    ├── PixelPreview.tsx   # 像素矩阵网格展示（校准预览和编辑器共用）
    ├── RoiCanvas.tsx      # 框选画布（步骤 02）
    ├── GridCanvas.tsx     # 网格叠加画布（步骤 03 对齐参考）
    └── steps/             # 四个步骤页面，纯展示组件，props 由 App 传入
        ├── UploadStep.tsx     # 01 上传
        ├── CropStep.tsx       # 02 框选
        ├── CalibrateStep.tsx  # 03 校准（占位矩阵 + 网格参数 + 阈值）
        └── EditStep.tsx       # 04 编辑与导出（画笔/橡皮/吸管/撤销/导出 PNG）
```

## 数据流

两条管线在框选后分流（`classifyImage` 自动判断，也可在框选页手动指定），产出同一个 `PixelMatrix` 后汇合：

```
                         ┌─ 图纸: detectGrid → analyzeOccupancy → Otsu + 人工 flips → occupancy
File → imageToRaster → 框选 ROI ┤
                         └─ 像素图: detectPixelArt（FFT/梯度估计格子数 → comb 细化 → 网格线吸附
                                    → 中位数采样 → 背景洪水置空 → 量化）
Raster + GridState (+ occupancy) → recognizeMatrix / samplePixelMatrix → PixelMatrix
PixelMatrix（+ 编辑/撤销重做）→ renderMatrix（+ floatingBlockOffsets 悬空块偏移）→ PNG 下载
```

像素图模式的 `GridState.roi` 会收紧到图案外接框（去掉背景白边），保证校准页改行列数时按图案范围均分。

## 测试

- `tests/pixel.test.ts` / `quantize.test.ts` / `repair.test.ts`：核心算法单元测试。
- `tests/classify.test.ts` / `pixelart.test.ts` / `fft.test.ts`：像素图模式（类型判断、网格估计、采样置空），含真实像素图回归（`inputs/小鸟像素图.png`、`伊布像素图.png`）。
- `tests/xiaohei-regression.test.ts`：真实图纸（`inputs/` 下 PNG）回归测试，改检测/占位算法后必须跑通。
- `tests/debug-*.test.ts`：调试辅助，会往 `outputs/` 写中间图（debug-color/debug-occ/sweep），排查识别问题时用。
- domain 层不依赖 DOM，`vitest` 直接在 Node 环境跑；`renderMatrix` 里对 `ImageData` 做了降级。

## 开发约定

- **导入路径**：ui 和 tests 一律从 `../domain/pixel` 导入，不直接引子模块。新增 domain 模块时在 `pixel.ts` 加一行 `export *`。
- **注释**：算法里的魔数和阈值（如 INK_DISTANCE、0.8 分位数、±15% 平局）都有"为什么"注释，改参数时同步更新注释和 `docs/算法说明.md`。
- **状态管理**：没有引入状态库；所有状态在 `App.tsx` 的 useState/useMemo 里，步骤组件只收 props。新功能需要跨步骤共享的状态加在 App，只服务单个步骤的状态可以留在该组件内。
- **样式**：改界面样式只动 `styles.css`，组件内不写内联样式（像素色块等功能性颜色除外）。

## 常见改动入口

| 需求 | 改哪里 |
|---|---|
| 网格检测不准（图纸） | `domain/grid.ts`，真实图纸回归看 `debug-real.test.ts` |
| 有豆/空位误判 | `domain/occupancy.ts`（墨迹分数、Otsu） |
| 像素图网格/取色不对 | `domain/pixelart.ts`（+`fft.ts`），回归看 `pixelart.test.ts` |
| 图纸/像素图误判 | `domain/classify.ts`（格线支持率阈值），回归看 `classify.test.ts` |
| 颜色识别/合并 | `domain/matrix.ts`（采样）、`domain/quantize.ts`（量化） |
| 导出 PNG 结构 | `domain/repair.ts`（renderMatrix、悬空块） |
| 某步骤界面/交互 | `ui/steps/` 对应文件 |
| 新增步骤或调整流程 | `ui/App.tsx` + `ui/types.ts`（STEP_ORDER/STEP_LABELS） |
